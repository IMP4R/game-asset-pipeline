Здравствуйте. Это финальное письмо по ассету — приёмка. Вы писали контракт, исполнитель его исполнил и документировал каждый шаг; теперь нужно установить, соответствует ли результат РЕФЕРЕНСУ. Никаких наших предварительных мнений: нужен ваш независимый вердикт.

МАТЕРИАЛЫ (всё ниже — источник истины):
1. Контракт (ТЗ). Обратите внимание: в нём каждое утверждение имеет статус (OBSERVED / HYPOTHESIS / PRODUCTION_CHOICE / UNRESOLVED), есть канонические экранные ограничения с допусками, инструкция посадки, и — важно — КОНТРАКТ ЯВЛЯЕТСЯ ПРОВЕРЯЕМОЙ ГИПОТЕЗОЙ, а не высшим эталоном. Если сборка соответствует контракту, но нормализованная проекция расходится с референсом, приёмка обязана признать соответствующую часть контракта неверной.
2. build_log исполнителя (пошагово, со статусами шлюзов и таблицами допусков).
3. Рендеры и маски: по каждой позе — reference crop, normalized reference mask, normalized render mask, overlay 50/50, XOR/difference, silhouette, beauty. Всё в нормализованном масштабе (ширина корпуса приведена к одной величине).
4. Референсы-кадры.

ЗАДАЧА (строго в этом порядке).

1. ПРОВЕРКА ПРИГОДНОСТИ ДОКАЗАТЕЛЬСТВ. Есть ли нормализованные пары, flat-маски, silhouette/XOR, численные измерения. Если чего-то нет — это ограничивает всё дальнейшее; перечислите.

2. ПРОВЕРКА КОРПУСА БЕЗ МАТЕРИАЛОВ (по каноническим ограничениям контракта и по нормализованным парам):
- upright: ширина рта, толщина кромки, доля полости, силуэт;
- inverted: доля видимой полости, ширина/высота купола, silhouette IoU.
По каждому пункту: PASS / FAIL / INSUFFICIENT_EVIDENCE + обоснование. Если FAIL — назовите, КОНТРАКТ или СБОРКА виноваты, и это разные правки.

3. ПРОВЕРКА ВНЕШНИХ ТЁМНЫХ ОБЛАСТЕЙ:
- доказано ли владение пикселями (объект / ячейка / сосед / тень / outline)?
- проходит ли выбранный модельный класс обе позы одной геометрией?
- не смешаны ли физическая деталь, обводка и тень?
Если область не разделена — приёмка не имеет права утверждать её посадку как физического меша. Вердикт: НЕ ПРИНЯТО: CLASSIFICATION_UNRESOLVED; действие — возврат к этапу классификации слоя, а не пересадка предполагаемой детали.

4. ТОЛЬКО ЗАТЕМ: материалы, состояния, экспорт, бюджет.

5. ИТОГ по каждому критическому элементу (Body, Mouth, InvertedDome, ExternalDarkLayer) — один статус: CONFIRMED / MISMATCH / INSUFFICIENT_EVIDENCE / WRONG_MODEL_CLASS. Статус MISMATCH или WRONG_MODEL_CLASS автоматически запрещает итог «принять после правок», если патч-лист запрещает менять этот элемент.

6. ИТОГОВЫЙ ВЕРДИКТ (одна строка): принять / принять после правок / вернуть на конкретный этап (какой) / остановить: CLASSIFICATION_UNRESOLVED.

РЕШЕНИЯ (если правки нужны): для каждого существенного расхождения — минимальная механическая правка в обозначениях исполнителя, с указанием, к какому элементу относится (корпус / деталь / камера / состояние) и какой статус она меняет. Если правка требует данных, которых нет, — назовите, каких.

Ограничения: не смягчайте вердикт из вежливости; не расширяйте правки за пределы материалов; не предлагайте переделывать то, что совпадает; не считайте «соответствует контракту» достаточным, если проекция расходится с референсом.
