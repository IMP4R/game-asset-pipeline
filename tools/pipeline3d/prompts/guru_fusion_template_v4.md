## Статус утверждений (обязателен)

Каждое утверждение в контракте имеет один из статусов:

OBSERVED — прямо измерено на референсе;
HYPOTHESIS — правдоподобное объяснение наблюдения;
PRODUCTION_CHOICE — техническое решение, принятое для реализации;
UNRESOLVED — не разрешено имеющимися кадрами.

Ни одно HYPOTHESIS или PRODUCTION_CHOICE не может быть использовано как критерий приёмки вместо OBSERVED.

## Канонические экранные ограничения корпуса (обязательны, заполнить ДО фиксации профиля)

Для ОБЕИХ поз числа с допуском, нормированные к ширине корпуса:

Upright:
- mouth_outer_width / body_width = [измеренное ± допуск];
- mouth_inner_width / body_width = [измеренное ± допуск];
- rim_visible_thickness / body_width = [измеренное ± допуск];
- cavity_area / body_area = [измеренное ± допуск].

Inverted:
- visible_cavity_area / body_area = [измеренное ± допуск];
- dome_width / body_width = [измеренное ± допуск];
- dome_height / body_height = [измеренное ± допуск];
- silhouette IoU (нормализованный) не ниже [порог].

## Шлюз 0 — калибровка проекции (добавлен после провала сборки 2026-09-25)

Все экранные отношения ниже зависят от высоты камеры. Без её калибровки измерение этапа 1 (снято с эталона) и силуэт рендера несопоставимы, и провал профиля недоказуем.

Правила:
- Сборщик ДО проверки профиля подбирает свободные параметры камеры (elevation, azimuth, орто-масштаб) по контрольным точкам, присутствующим в обеих позах: ширина рта (внешняя и внутренняя), видимая толщина кромки. Совпадение — в пределах контрактных допусков.
- Статус шлюза 0: `PROJECTION_CALIBRATED` или `PROJECTION_UNRESOLVED`.
- Если шлюз 0 не пройден, профиль НЕ может быть объявлен неверным: допустимы только `PROJECTION_UNRESOLVED` / `INSUFFICIENT_EVIDENCE`. `PROFILE_INVALID` ставится исключительно ПОСЛЕ успешного шлюза 0.
- Метрики, зависящие от проекции (ширины по высоте, полость, купол, silhouette IoU), проверяются только после шлюза 0.
- Неустойчивые метрики (строка `y/H = 1.00` на перекрытой или антиалиасингованной нижней границе) исключаются из обязательного набора; если граница наблюдаема полностью — используется устойчивая нижняя полоса.

ПРАВИЛО НЕЗАВИСИМОСТИ (обязательно, добавлено после петли 2026-09-25): любой проверочный шлюз обязан иметь критерий, НЕ ЗАВИСЯЩИЙ от проверяемой гипотезы. Калибровка проекции — по глобальному силуэту (максимум IoU по перебору угла, порог калибровки ниже строгих порогов приёмки), а не по значениям, которые сама гипотеза и задаёт. Ошибки отдельных якорей не провалят калибровку, а помечают гипотезу подозрительной (PROFILE_SUSPECT) для разбора в следующем шлюзе. Иначе возникает петля: гипотезу нельзя признать неверной до калибровки, а калибровка не может пройти при неверной гипотезе.

## Правила слияния

1. Несущие поверхности: форма/профиль/пропорции берутся из ответов, но в статусе HYPOTHESIS/PRODUCTION_CHOICE с привязкой к каноническим ограничениям выше. Если между ответами конфликт чисел — строка «конфликт: X против Y; взято Z, потому что…». Диапазоны разрешаются пересечением; если пересечения нет — геометрический ответ для несущих, логический для частей.

2. Внешний тёмный слой (тёмная область вокруг объекта) по умолчанию НЕ включается в ассет, пока не доказано владение. Классы: ATTACHED_PHYSICAL_PART / HOLDER_OR_NEIGHBOR / CONTACT_SHADOW / SCREEN_SPACE_OUTLINE / MIXED / UNRESOLVED. Если UNRESOLVED — контракт выпускает только корпус, а слой помечает UNRESOLVED_EXTERNAL_LAYER и запрещает его встраивать. Если выбран ATTACHED_PHYSICAL_PART, укажите, что маска детали обязана одновременно проходить допуски во ВСЕХ эталонных позах; улучшение одной позы за счёт другой = опровержение класса, а не повод деформировать дальше.

3. Профиль z/r — ТЕКУЩАЯ ГИПОТЕЗА РЕАЛИЗАЦИИ, не неприкосновенная истина. Сборщик не вправе менять профиль произвольно. Но если нормализованный flat-mask рендер корпуса не проходит хотя бы одно каноническое ограничение выше (upright или inverted), сборщик обязан: пометить PROFILE_INVALID; приложить маски и численные расхождения; остановить выпуск корпуса; вернуть контракт на пересмотр профиля. Запрещено принимать корпус только потому, что он буквально воспроизводит прежнюю z/r-таблицу.

4. Кромка устья воспроизводит наблюдаемую экранную толщину и раскрытие. Физически правдоподобная толщина не имеет приоритета над экранной проекцией. Если референс показывает тонкую видимую кромку и широкий раструб, запрещено увеличивать толщину/радиус скругления ради ощущения «пластиковости».

5. Правило inverted: rigid-поворот 180° — гипотеза состояния, не обязательное требование. Принимается, только если после поворота корпус одновременно проходит upright- и inverted-ограничения. Если inverted-референс требует гладкого купола при почти невидимой полости, контракт обязан явно определить допустимый способ получить это состояние: отдельный presentation mesh; state-dependent occluder; иная подтверждённая геометрия; либо запрос дополнительных данных. Запрещено считать наличие реальной полости достаточным оправданием видимого кратера в inverted-позе.

6. Полость: наличие реальной геометрической полости — PRODUCTION_CHOICE; то, что она ВИДНА в конкретной позе, — OBSERVED-факт из кадров. Не противоречьте наблюдению ради «правдоподобности».

## ПРОТОКОЛ ПРИЁМКИ (переносится в контракт дословно)

- Каждая часть (корпус, любая утверждённая деталь, внешний слой) получает статус приёмки: CONFIRMED / MISMATCH / INSUFFICIENT_EVIDENCE / WRONG_MODEL_CLASS. Статус MISMATCH или WRONG_MODEL_CLASS автоматически запрещает итог «принять после правок», если патч-лист запрещает менять этот элемент.
- Часть невидимая во всех позах — провал приёмки независимо от геометрии.
- Посадка/форма любой утверждённой детали проверяется по правилам посадки (пункт ниже) и по каноническим ограничениям.
- МАСШТАБНАЯ НОРМАЛИЗАЦИЯ обязательна: все сравнения — только после приведения ширины корпуса рендера и референса к ОДНОЙ величине. Никаких суждений по кадрам разного масштаба.
- Сравнительный лист: только пары реф|финал в равном масштабе, служебные кадры в лист не включаются.

## Универсальная инструкция посадки (для любой утверждённой физической детали)

Для каждой такой детали: (1) найти её на КАЖДОМ эталонном кадре; (2) снять положение в экранных координатах каждого кадра (примыкание, доли ширины/высоты, края, наклон/провис); (3) выразить относительно опорных элементов самого объекта; (4) посадить так, чтобы проекция в КАЖДОЙ позе совпала с кадром; (5) запреты: не наследовать координаты других частей, не выравнивать параллельно соседней кромке при видимом наклоне/провисе. Если деталь не различима на кадрах — остановиться и запросить материалы, а не оценивать «по общим соображениям».

## На выходе

Один связный самодостаточный контракт: наблюдения со статусами; выбранные гипотезы с обоснованием; канонические экранные ограничения с числами и допусками; неизвестные (UNRESOLVED) с указанием, что нужно для их разрешения; модельные классы с матрицей «объясняет ли обе позы»; явные точки возврата (PROFILE_INVALID, MODEL_CLASS_REJECTED); протокол приёмки; порядок сборки и экспорт. Ничего не подразумевайте из исходников.
