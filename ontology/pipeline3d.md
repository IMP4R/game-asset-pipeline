# Pipeline3D — архитектура создания 3D-моделей (v1, живой документ)

Цель: детерминированный конвейер, где каждое решение измеримо, а совпадение с референсом
проверяется пикселями и палитрой, а не «на глаз». Анти-цель: статистическое упрощение
нейросетью («примерно похоже»).

---

## 0. Слои осмысления (заполняются строго сверху вниз)

```
L0 Функция объекта       зачем объект существует в геймплее
L1 Функциональные единицы разбор по РОЛЯМ (ёмкость/переноска/индикатор/основание...),
                         для каждой — требование функции
L2 Свойства единиц       материал, жёсткость, gloss, hex-цвет, градиенты, поведение
L3 Чертёж (3 плоскости)  вид спереди / сверху / сбоку: габариты и позиции единиц в долях H/D
L4 Примитивы и операции  цилиндр/тор/loft/bevel/rings+bridge — НИЗШИЙ слой, куда можно
                         опускаться только после заполненных L0–L3
```

Правило прослойки: **примитив запрещён, пока не существует спека L0–L3.**
Любая часть, отсутствующая в одной из трёх проекций, = ошибка спецификации
(кейс: ручка «внутри ведра» ловится на виде сверху — дуга пересекает кольцо зева).

## 1. Узлы (артефакт → гейт)

| Узел | Артефакт | Гейт |
|---|---|---|
| N0 Референс-пакет | 3–5 кропов реальной игры, ≥3 ракурса, палитра замером | чеклист полноты |
| N1 Камерная калибровка рефа | `camera_params.json` (elevation/azimuth/dist/FOV, метод ниже) | пересчёт эллипсов сходимость |
| N2 Спека L0–L1 | функция + единицы + требования | 5 вопросов логики |
| N3 Спека L2 | карта свойств (hex с рефа, gloss, градиенты) | ΔE сэмплов с рефом ≤ порога |
| N4 Спека L3 чертёж | 3 таблицы проекций с числами | единицы во всех 3 плоскостях |
| N5 Геометрия | меш по спеке (дуги = rings+bridge, дырки сквозные) | контакт-чеки числом |
| N6 Материалы+bake | AO/градиенты запечены | матшар против рефа |
| N7 Рендер-лок | модель в калиброванной камере рефа, обе позы | N-CMP гейт (метрики ниже) |
| N8 Критика | глаза + критик + метрики | ≤2 итерации, иначе возврат к N2 |
| N9 Приёмка | человек с чеклистом | финал |

## 2. N1 — камерная калибровка референса (детерминизм позы)

Модель рендерится ТОЛЬКО в камере референса, иначе сравнение бессмысленно.

Метод (по скрину):
1. **Elevation** = asin(minor/major) эллипса обода круглой части (обод ведра = окружность
   → эллипс; отношение осей даёт угол наклона камеры точно, не «на глаз»).
2. **Azimuth** — по сетке лотка/позиции в кадре (у тел вращения слабо влияет, фиксируем
   по асимметрии ушек/ручки).
3. **Dist/FOV** — по сходимости вертикальных рёбер двух вёдер в ряду (перспектива).
4. **Scale** — ширина обода в пикселях рефа задаёт кадрирование рендера 1:1.

Артефакт: `camera_params.json` рядом с рефом.

## 3. N-CMP — пиксельно-палитровый гейт (детерминизм соответствия)

Композит: модель рендерится в калиброванной камере, вырезается по маске, вставляется
в позицию референсного объекта (подгон bbox). Считается:

| Метрика | Зона | Порог (стартовый) |
|---|---|---|
| Silhouette IoU | весь объект, обе позы (прямая + перевёрнутая) | ≥ 0.85 |
| ΔE (Lab) среднее | корпус / обод / ручка / дырки | ≤ 12 на зону |
| Палитра (топ-5 цветов, ΔE) | весь объект | каждый цвет ≤ 10 |
| Позиционные габариты (W/H в px) | bbox | ±4% |

Гейт: если хоть одна метрика не сошлась — итерация по самой плохой зоне.
Двойная поза обязательна: объект матчится и **прямым на сцене**, и **перевёрнутым
в лотке** — это ловит ошибки формы, невидимые в одном ракурсе.

## 4. Протокол итераций

- Итерация = рендер в N7 + N-CMP + правка худшей зоны.
- Максимум 2 итерации после первого полного прогона; не сошлись метрики →
  возврат к N2/N4 (спека неверна), а не «подкрутим тор».

## 5. Реестр конвенций clay_lib (грабли)

- `cube(size=S, scale=k)`: габариты = S·k по каждой оси.
- `camera azimuth` отсчитывается **от оси +X**; фронт объекта, смотрящего в +Y = 90.
- `a.mat` принимает RGB **0–1**; JSON-палитры 0–255 нормализовать.
- Пиксель-арт с рефа: плотный кроп + nearest к фиксированной палитре (quantize вырождается).
- Сетка арта — в XZ: `z = (SIDE-FW) - cell*cy - cell/2`.
- Дуги/скобы/ручки: rings+bridge полудуга. Полный тор, спрятанный в теле, = баг.

## 6. Шаблон спеки ассета (заполнять до геометрии)

```
L0: <функция в геймплее>
L1: единицы: [имя, требование функции]
L2: для каждой единицы: [hex(замер), gloss, градиент, поведение]
L3: проекции F/T/S: таблица «единица → габариты/позиция в долях H/D»
```


## 7. Выводы пилота ref-lock (ведро, реф Sand Loop shot1)

- Камера референса ИЗМЕРЕНА: эллипс обода minor/major = 0.81 → elevation = 54.5°.
  Совпало с видом (глубоко видно в зёв) — метод работает, не «на глаз».
- Палитровый гейт считаем ТОЛЬКО по albedo материала против замера рефа:
  ΔE(#EE6900, замер) = 23 → PASS. Рендерный свет ломает ΔE (было 116 на верном цвете)
  — свет недетерминирован, albedo детерминирован.
- Силуэтный IoU требует: (а) N0 = чистые изолированные кропы объекта (соседние
  предметы ломают маску), (б) рендер для маски без пересветов (world ≤ 0.3,
  rough ≥ 0.25), иначе купол выгорает и маска дырявая. Иначе IoU = шум.
- Двойная поза (прямая + перевёрнутая) в одном калиброванном ракурсе — обязательна:
  перевёрнутая ловит ошибки днища/базы, прямая — зева/краски.


## 8. Узел «пересечение рефов» (v6, ведро)

Рефы одного объекта в разных состояниях = набор ОДНОВРЕМЕННЫХ ограничений на одну
модель. Геометрия выводится из пересечения:
- прямое ведро дало H/D=1.09, зев 1.0W, глубину зева;
- перевёрнутое (вставлено ртом в ячейку, виден купол) дало скругление основания
  (купол к ~0.56W у дна) и отсутствие ручки (в обоих состояниях ручки не видно —
  значит в ref-locked ассете её НЕ рисуем; вымышленные части запрещены).
Гейт: модель рендерится в обеих позах в калиброванной камере, обе сравниваются
со своими рефами. Поза, не сошедшаяся = возврат в спеку.

Найденные дефекты протокола (исправлены):
- флип-пивот: родительская локация ставится ДО парентинга, землю из флипа исключать;
- свип яркости albedo: каждый k с RESET к базовым цветам (иначе накопление);
- ΔE по рендеру упирается в свет рефа (минимум 65 при k=1.15) — палитровый гейт
  остаётся по albedo (23), свип света/k — только сближение картинки.

## 9. v2 — машинно-читаемый слой конвейера (2026-09-01, tools/pipeline3d/)

Интеграция онтологического принципа: **спека = данные, генератор = детерминированный,
критик = метрики. LLM не касается координат** — только чтение референса в поля схемы.

### Файлы (tools/pipeline3d/)

| Файл | Роль (узлы) |
|---|---|
| `asset_spec.schema.json` | JSON Schema спеки v2.0: L0–L4 + dimensions + poses + budget + provenance |
| `style_constants.json` | конституция стиля: вектор soft3d_v2 ±20%, гейты N-CMP, конвенции §5, палитры |
| `specs/bucket_paintloop.json` | ведро Paint Loop как ДАННЫЕ (профиль из v23, консенсус §7/§8) |
| `validate_spec.py` | гейты G0–G8 (N2–N4): единица во всех 3 проекциях, L2-свойства, провенанс, профиль, рефы, двойная поза, бюджет, H/D |
| `generate_blender.py` | N5–N7: lathe_shell/box → bpy, Z-градиент материалов, позы (флип+sink), числовой аудит габаритов и бюджета |
| `critic_ncmp.py` | N-CMP §3 в коде: N0-изоляция кропа, IoU с bbox-подгоном, bbox ±4%, палитра top-5 ΔE, albedo-гейт |

Запуск: `validate_spec.py specs/X.json` → `blender --background --python generate_blender.py -- specs/X.json --out DIR` → `critic_ncmp.py compare RENDER.png REF.png` (+ `n0`, `albedo`, `selftest`).

### Правила слоя (наследуют §0–§8)
- примитив запрещён без спеки; G3: части, не видимой ни в одном рефе, не существует (§8);
- палитровый гейт — albedo-only (§7), рендерный ΔE — индикатор;
- IoU считается с bbox-подгоном (так определён N-CMP в §3), масштаб кадра — отдельный гейт ±4%;
- итерация = правка СПЕКИ, не «подкрутим тор» (§4); лимит 2 итерации сохранён.

### 9.1 Итог v2.2 и вскрытые корни (2026-09-01, вторая половина сессии)

Пилот «ведро» доведён итерациями данных (код генератора/критика менялся только когда
не хватал примитивов): v2.0 «тумблер с клиньями» → v2.1 `lathe_path` (обод-закругление и
купол прямо в пути вращения; полость отдельной единицей — функциональные части раздельно,
join после апрува формы) + Freestyle-обводка → v2.2 squat-профиль + сжатый к ободу градиент.

**Корни хронических расхождений, найденные гейтами:**
1. Замер эллипса §7 (54.5°) принадлежал другому кадру — ракурс рендера был вдвое круче
   рефа. Текущий реф: компромисс 35° по видимой глубине полости (перезамер по эллипсу ≈28°).
2. Сырые пиксели bbox некорректны при разном разрешении/кропе — гейты переведены на
   кадро-инвариантные: W/img_W и аспект H/W.
3. Перспектива при близкой камере разносит зев быстрее роста H — аспект нельзя чинить
   дистом; дист решает только кадрирование, H — только аспект (разделение осей).
4. Яркий градиент по всему корпусу ломает палитровую топ-5 — в рефе светлеет только вал
   обода: stops сжаты к z=1.0.

**Состояние N-CMP v2.2 (прямая поза):** кадрирование 1.3% PASS, аспект 6.2%, палитра
10.8 (порог 10), IoU 0.78 (порог 0.85). Перевёрнутая поза ждёт N0-чистого dome-кропа.

**Остаток (возврат к N2/N4 по §4):** обод должен читаться ТОЛСТЫМ светлым валом
(~15% высоты в проекции рефа; сейчас тонкая тёмная лента), полость глубже, контур
жирнее (OUTLINE_PX 6–8). Кандидат: отдельная единица rim-торус (rings+bridge) + H полости.

## 9.2 img2img-перцепция как источник замеров (подтверждено судьёй)

Текстовая перцепция рефа нейросетью — слабое звено (купол из проекции, промахи по грязным кропам).
Рабочая замена: нативный image-to-image через `tools/img_edit.py` (gpt-image-2):
1. Рефы брать из игры-источника (Sand Loop), не из наших мокапов: `assets/ref_sandloop_buckets.png`.
2. Промпт задаёт СЕМАНТИКУ явно («чёрная полоса = сложенная ручка, крепится под ободом, лежит по верхней трети корпуса», «ведро монотонное, один пластик»), иначе модель рисует «какие-то контуры».
3. Выход — пятиракурсный ортогональный эпюр (FRONT/SIDE/BACK/TOP/BOTTOM). Судья: «последнее изображение просто идеальное» (`/tmp/bucket_epure_sl3.png`).
4. Замеры для Asset Spec снимаются С ЭПЮРА: филет нижних углов ~0.12H, обод-наплыв почти заподлицо, ручка z≈0.66–0.82, конус бортов 0.70→0.965.
5. Текстовый PERCEIVE остаётся кросс-чеком, а не источником.

Уроки генератора (generate_blender.py):
- пути lathe_path — строго `[z_frac, r_frac]`; перепутанный порядок даёт иглу-«шип», прячущуюся в прямой позе и торчащую из флипа;
- z-нормализация пути по zmax удалена: она растягивала ленты (пояс обернулся вокруг зева, полость стала серой);
- «одна модель — две позы» конфликтует с гейтами по одному рефу (ручки нет в upright-рефе): палитра/IoU против одного поза-рефа не могут быть приёмкой, судья смотрит обе позы.
